## Known Limitations

1. **Brute force protection** (TC-025): Requires `app.set('trust proxy', true)` in Express to work behind nginx in Docker. This is a local-dev limitation; production deployments with proper proxy config would resolve it.

2. **Audit logging backend** (TC-022, TC-048): Auth events are logged to Redis for performance, not PostgreSQL. The PostgreSQL `audit_logs` table exists for immutability compliance. A future enhancement could add a Redis→PostgreSQL flush mechanism.

3. **Feature flag system** (TC-045, TC-046, TC-047): No feature flag REST API exists. Flags are managed via environment variables and config files. Implementing a proper feature flag service (e.g., Unleash) would add this capability.

4. **Webhook endpoint** (TC-066): No webhook receiver is configured. This would require implementing a POST endpoint with signature verification middleware.

5. **SPA client-side routes** (TC-069, TC-070): `/auth/login` and `/auth/register` are client-side only. Adding Next.js SSR for these pages or configuring nginx rewrites would make them server-renderable.
